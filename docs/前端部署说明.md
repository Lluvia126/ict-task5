# 前端部署说明（本地开发 + 云服务器上线）

前端是 **Vite 6 + Vue 3 + Element Plus**，位于 `ict-task5/frontend`。
核心原则：**浏览器只访问一个源**，`/api` 由代理转发到后端 → 没有跨域问题，也不用配 CORS。

## 一、本次修复的问题（之前"功能无法实现"的原因）

| # | 问题 | 影响 | 修复 |

## 二、本地开发（现在就能用）

```powershell
cd D:\ICT\procurement-engine\ict-task5\frontend
npm install          # 依赖已装可跳过
npm run dev          # http://localhost:5173
```
前提：后端在本机 `127.0.0.1:8000` 运行（`uvicorn main:app --host 127.0.0.1 --port 8000`）。

**数据流**：浏览器 → `http://localhost:5173/api/...` → vite 代理 → `http://127.0.0.1:8000/api/...`
（同源，无跨域；`.env.development` 里 `VITE_API_BASE_URL=` 留空即表示同源。）

**验收**：
- 页面路由 `/dashboard` `/upload` `/extractions` `/relations` 都能打开
- `http://localhost:5173/api/health` 返回 `{"status":"ok",...}`
- 页面能看到抽取结果列表（当前库里有 10 条左右）

**换后端地址**（比如后端在另一台机器）：
```ini
# frontend/.env.development
VITE_API_BASE_URL=
VITE_PROXY_TARGET=http://<后端IP>:8000
```
改完重启 `npm run dev`。

## 四、部署到云服务器（推荐：前端和后端同一台）

### 1. 构建并上传
```powershell
cd D:\ICT\procurement-engine\ict-task5\frontend
npm run build
scp -r dist ubuntu@<云主机IP>:/opt/ict-task5-frontend/
```
（服务器上先 `sudo mkdir -p /opt/ict-task5-frontend`）

### 2. Nginx 配置（同源 + SPA + /api 反代）

`/etc/nginx/conf.d/ict-task5.conf`：
```nginx
server {
    listen 80;
    server_name demo.你的域名;          # 没有域名就写公网 IP
    root /opt/ict-task5-frontend/dist;
    index index.html;

    # SPA（history 路由）：刷新 /dashboard 不会 404
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 业务后端（注意 proxy_pass 结尾不要带斜杠，保留 /api 前缀）
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;         # AI 抽取可能较久
        client_max_body_size 200m;       # 允许上传大 ZIP
    }

    location ~* \.(js|css|png|jpg|jpeg|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```
```bash
sudo nginx -t && sudo systemctl reload nginx
```

### 3. 公网入口（二选一）

**方案 A（推荐，前端后端一起走隧道，免备案）**
Cloudflare 隧道里加一个 Public Hostname：`demo.你的域名` → `http://127.0.0.1:80`。
这样只暴露 Nginx，一个域名同时提供页面和 `/api`，**完全同源**。

**方案 B（前端放 Cloudflare Pages）**
- `frontend/.env.production` 改成：`VITE_API_BASE_URL=https://api.你的域名`
- 重新 `npm run build` 后上传 `dist` 到 Pages
- 后端 `.env` 的 `ALLOWED_ORIGINS` 要加 `https://demo.你的域名`

> 说明：同源方案（A / 同机 Nginx）**不需要**配 CORS，也不需要在后端加前端域名。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 页面能开但没数据，Network 里全是 `/api/api/...` 404 | `VITE_API_BASE_URL` 写成了 `/api` 或 `http://x:8000/api` → 应为**空**或**只到端口** |
| 刷新 `/dashboard` 变 404 | Nginx 缺 `try_files $uri $uri/ /index.html` |
| 浏览器报 CORS | 前后端不同源，且后端 `ALLOWED_ORIGINS` 没放行前端域名 |
| 上传大 ZIP 报 413 | Nginx `client_max_body_size` 太小 |
| 抽取请求 504 | Nginx `proxy_read_timeout` 太小（设 300s） |
| 改了后端地址但页面还是旧地址 | `.env.*` 改完必须重启 `npm run dev` / 重新 `npm run build` |
| `npm run build` 报 `spawn EPERM` | 只在受限终端出现；正常 PowerShell 直接运行即可 |
