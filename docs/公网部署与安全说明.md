# 公网部署与安全说明（初赛提交版）

面向评委"直接访问网址测试、免登录"的场景：**只对外暴露后端一个端口**。
Neo4j 与 SQLite 只留在后端本机；AI 抽取服务在前端那台机器上，只走后端→前端局域网调用，
两者都不暴露到公网。不买服务器、不做路由器端口映射。

---

## 0. 目标架构

```
        评委浏览器（校外 4G / 任意网络）
                 │ HTTPS
                 ▼
        内网穿透（cloudflared / cpolar）      ← 免费，本机出站连接，无需公网 IP
                 │ http://127.0.0.1:8000
                 ▼
   ┌──────────── 后端机器（跑隧道的那台）────────────┐      ┌───── AI 机器（前端那台）─────┐
   │  FastAPI 后端  127.0.0.1:8000  ← 唯一对外暴露    │      │  AI 抽取服务 :8000          │
   │  Neo4j         localhost:7687/7474 ← 不暴露      │─局域网→│  只允许后端机器访问          │
   │  SQLite        data/*.db       ← 文件，不对外    │      └─────────────────────────────┘
   └─────────────────────────────────────────────────┘
```

要点：
1. 后端用 `--host 127.0.0.1` 启动，**不要 0.0.0.0**：只有本机的隧道进程能访问它。
2. 后端机器的 Windows 防火墙**不要**放行 8000 / 7474 / 7687 入站规则。
3. 隧道进程是出站连接，不受防火墙入站限制。
4. **AI 服务目前在前端那台电脑上**（与后端不同机），后端通过局域网 IP 调用它
   （`.env` 的 `AI_SERVICE_URL=http://<前端局域网IP>:8000`）。因此：
   - 隧道只转发后端，**不要**给 AI 服务也开隧道/端口映射；
   - AI 机器上建议加一条防火墙入站规则：**只允许后端机器的 IP** 访问该端口，
     不要对整段校园网开放（AI 服务自身没有鉴权）；
   - 以后如果改成同机部署，AI 服务改监听 `127.0.0.1:8001`，
     同时把 `AI_SERVICE_URL` 改成 `http://127.0.0.1:8001`。

## 1. 公网访问方案（三选一，都不花钱）

### 方案 A（推荐）Cloudflare Tunnel
免费、自动 HTTPS、不需要公网 IP 和备案，隧道挂了换个地址即可。

```powershell
# 1) 下载 cloudflared.exe（Windows amd64）放到 D:\tools\cloudflared\ 并加入 PATH
# 2) 快速隧道（地址每次重启会变，够用）
cloudflared tunnel --url http://127.0.0.1:8000
# 输出形如：https://xxxx-yyyy.trycloudflare.com
```
> **校园网实测（2026-10-16，后端机器）**：学校网络封了 UDP/TCP **7844**，
> cloudflared 默认的 QUIC 连不上边缘节点（日志里 precheck 报 `QUIC connection failed`
> / `dial tcp ...:7844: i/o timeout`），必须加 `--protocol http2` 强制走 443：
> ```powershell
> cloudflared tunnel --url http://127.0.0.1:8000 --protocol http2
> ```
> 日志出现 `Registered tunnel connection` 才算真正建立；否则会一直重试。
> 一键启动（含后端、端口探测、地址打印）：`powershell -ExecutionPolicy Bypass -File scripts\public_demo.ps1`

想要**固定地址**：注册 Cloudflare 免费账号 → 绑一个免费域名 → `cloudflared tunnel login` →
`cloudflared tunnel create ict-task5` → `cloudflared tunnel route dns ict-task5 demo.你的域名` →
`cloudflared tunnel run ict-task5`。这样地址长期不变，前端配置一次即可。

### 方案 B cpolar（你们机器上已经装过安装包）
```powershell
cpolar http 8000
# 免费版会给一个随机域名，可在 cpolar 后台看；重启会变
```

### 方案 C ngrok
```powershell
ngrok http 8000
```

> 演示当天把隧道窗口保持打开（可最小化，但不要关）。地址变化时只需要改**前端**的 API 地址配置。

## 2. 每次演示的启动顺序

```powershell
# ① 图数据库
docker start neo4j

# ② 后端（注意：生产不要加 --reload）
.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000

# ③ 隧道（后端机器上执行）
cloudflared tunnel --url http://127.0.0.1:8000
```

AI 服务在**前端那台电脑**上单独启动（它的负责人维护），后端通过 `.env` 的
`AI_SERVICE_URL` 调用：

```ini
AI_SERVICE_URL=http://<前端局域网IP>:8000     # 现状：跨机部署
# AI_SERVICE_URL=http://127.0.0.1:8001       # 以后改成同机部署再用这行
```
前端局域网 IP 变化时改这一行并重启后端即可；用 `GET /api/ai/health` 可快速确认能否连通。

## 3. 接口安全（已实现，`services/security.py`）

### 3.1 接口分级

| 接口 | 是否需要口令 | 保护方式 |
|---|---|---|
| `GET /api/health`、`/api/extractions`、`/api/extractions/{id}`、`/api/pairs`、`/api/export*`、`/api/analysis/*`（查询） | 否 | 只读，评委免登录使用 |
| `POST /api/upload`、`/api/upload-pair` | 默认否 | 类型白名单 + 大小上限 + 每 IP 每天配额（`QUOTA_UPLOAD_PER_IP_DAY`） |
| `POST /api/extract/{file_id}`、`/api/extract-pair/{pair_id}`（**产生 AI 费用**） | 默认否 | 每 IP 每天配额 + **全局每日上限**（`QUOTA_EXTRACT_GLOBAL_PER_DAY`） |
| `POST /api/parse*` | 否 | 每 IP 每天配额（CPU 保护） |
| `DELETE /api/extractions/{id}`、`DELETE /api/extractions`（删除/清空） | **是** | 必须 `X-Admin-Token` |
| `POST /api/analysis/graph/sync`（图谱重建） | **是** | 必须 `X-Admin-Token` |

口令校验逻辑：请求头 `X-Admin-Token: <ADMIN_TOKEN>`，**管理员调用不受配额限制**。
超限返回 `429`，未带口令返回 `401`；`PUBLIC_MODE=1` 且没配 `ADMIN_TOKEN` 时，
破坏性接口直接返回 `503`（fail-closed，避免公网裸奔）。

### 3.2 `.env` 安全配置

```ini
ADMIN_TOKEN=<用下面命令生成>
PUBLIC_MODE=1
ALLOW_ANON_UPLOAD=1        # 0 = 仅管理员可上传
ALLOW_ANON_EXTRACT=1       # 0 = 仅管理员可抽取（评委将无法自助测试任务三）
QUOTA_UPLOAD_PER_IP_DAY=10
QUOTA_EXTRACT_PER_IP_DAY=20
QUOTA_EXTRACT_GLOBAL_PER_DAY=300
MAX_UPLOAD_MB=100
ALLOWED_ORIGINS=https://你的前端域名
```

生成口令：
```powershell
.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(24))"
```

### 3.3 演示环境推荐配置（可直接复制到 `.env`）

```ini
ADMIN_TOKEN=<用下面的命令生成>
PUBLIC_MODE=1
ALLOW_ANON_UPLOAD=1
ALLOW_ANON_EXTRACT=1
QUOTA_UPLOAD_PER_IP_DAY=10
QUOTA_EXTRACT_PER_IP_DAY=20
QUOTA_EXTRACT_GLOBAL_PER_DAY=300
MAX_UPLOAD_MB=100
ALLOWED_ORIGINS=<前端实际访问地址，逗号分隔>
GRAPH_SYNC_MODE=auto
AI_SERVICE_URL=http://<前端局域网IP>:8000
```

### 3.4 已经覆盖的安全点

- **AI 服务、Neo4j 不暴露**：隧道只转发后端端口；Neo4j 只监听本机；
  AI 服务虽在另一台机器，但只走局域网、并由防火墙限制来源（见 §0 第 4 条）。
- **费用可控**：抽取有"每 IP + 全局每日"双配额，管理员不受限；`logs/access.log`
  记录 `bucket=extract` 的每一行调用（含 IP/时间/UA），可用于核算与溯源。
- **上传可控**：扩展名白名单（html/htm/zip/pdf/doc/docx/xls/xlsx/csv/txt/png/jpg）、
  大小上限、读内存前先用 `Content-Length` 预检超大请求。
- **CORS 收紧**：`ALLOWED_ORIGINS` 指定前端域名；只有配置为 `*` 时才放开所有来源。
- **错误不泄露**：Neo4j 不可用返回 503 + 提示，不吐堆栈；抽取失败返回简短 detail。
- **上传文件落地安全**：后端以 uuid 命名保存，不落地原始文件名，无路径穿越风险。

### 3.5 一个重要确认点

你们要求"免登录、评委能测任务三"，所以**上传/抽取默认是放开的**（靠配额兜住费用）。
如果老师要求更严（评委只做浏览，不测试上传），把 `ALLOW_ANON_UPLOAD=0`、
`ALLOW_ANON_EXTRACT=0`，改为评委用口令调用即可。

## 4. 数据保留与"正式数据 / 演示数据"区分

1. **唯一真相源是 SQLite**（`data/results.db`）。Neo4j 只是它的投影：
   - 删除/清空抽取记录会同时更新图谱；
   - `POST /api/analysis/graph/sync?mode=rebuild` 只重建图谱，**不会删 SQLite 数据**。
2. **历史演示数据已经清干净**：Neo4j 当前 0 节点 / 0 关系（已执行全量重建）。
   每条关系都带 `announcement_ids` 来源标记，查询只认"当前有效公告"，
   不会再出现"抽取 0 条、图谱还有旧关系"的情况。
3. **危险操作已加口令保护**：删除单条、清空全部、图谱重建都需要 `X-Admin-Token`，
   评委点不到、也调用不了。
4. **备份**（建议每天一次 + 正式数据入库后立刻一次）：
   ```powershell
   .venv\Scripts\python.exe -m scripts.backup_data
   # -> data/backups/20261016_2130/{results.db, pairs.db, uploads/, extractions.csv ...}
   ```
   可用"任务计划程序"每天定时执行。备份目录不进 Git（已在 `.gitignore`）。
5. **正式数据入库流程**：跑完约 1000 条官方基准数据 → `GET /api/export` 导出三表 CSV
   与数据库一起留档 → 交到提交文档；此后不要再执行"清空抽取记录"。

## 5. 前端需要配合的点

| 事项 | 说明 |
|---|---|
| API 地址可配置 | 隧道域名变化后只改前端配置，后端不动 |
| 下载 CSV 的 BOM | **后端已经加好 UTF-8 BOM**（响应前 3 字节 `EF BB BF`），前端直接下载原始文件即可：`const blob = await res.blob()` 后 `URL.createObjectURL(blob)` 下载，**不要再手动补 `\ufeff`**（会变成双 BOM）。只有当中间经过了 `res.text()`（会把 BOM 吃掉）才需要补；更省事的做法是直接 `window.location.href = apiBase + '/api/export/' + pairId` |
| 管理按钮 | "删除/清空/图谱重建"在后端需要口令，演示版建议不展示这些按钮，或把口令放前端私有配置 |
| CORS | 把前端域名加到后端 `ALLOWED_ORIGINS` |

## 7. 应急处理

| 情况 | 处理 |
|---|---|
| 抽取被刷 / 疑似费用异常 | 换 `ADMIN_TOKEN` → 设 `ALLOW_ANON_EXTRACT=0` → 重启后端；必要时直接关闭隧道窗口 |
| 想核对费用 | 统计 `logs/access.log` 中 `bucket=extract` 的行数 |
| AI 服务 IP 变化 | 改 `.env` 的 `AI_SERVICE_URL` → 重启后端 |
| 隧道地址变了 | 改前端 API 配置即可 |
| 图谱不一致 | `GET /api/analysis/graph/status` 看 `missing_in_graph` / `stale_in_graph`，再 `POST /api/analysis/graph/sync`（需口令） |
